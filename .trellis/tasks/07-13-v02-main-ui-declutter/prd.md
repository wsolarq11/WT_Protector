# V02 主界面视觉降噪

## Goal

降低主窗口顶部动作竞争，让高频启动路径和四个筛选框成为稳定视觉主线，同时保留全部现有命令、键盘路径和独立管理窗口。

## Confirmed Facts

- Cards 视图已只直接展示“启动 + 更多”，预演、排序、复制、编辑、删除均在上下文菜单；本任务不重复改卡片。
- 命令、模板和地址已迁移到独立管理窗口；主窗口仅需保留入口，不需要合并窗口或重构服务。
- `LauncherControlBar.axaml` 当前在标题区直接展示 4 个批量动作，在次级动作行直接展示新增、分组、发现、2 个管理入口、3 个启动组维护动作和计数，共 13 个并列交互元素。
- 启动组的应用、预演和启动已在“启动组”控制框内，保存/更新/删除属于低频维护操作。

## Requirements

- R1：高频动作保持直接可见：新增按钮、发现、启动已勾选、启动组选取/应用/预演/启动。
- R2：将“全选可见/清空/重新加载”折叠为一个可键盘访问的选择与刷新菜单。
- R3：将命令管理/地址管理折叠为一个管理菜单；继续调用现有命令，不合并窗口或 ViewModel。
- R4：将保存/更新/删除启动组折叠为一个启动组维护菜单；危险删除仍调用现有确认路径。
- R5：已勾选计数和可见/总数继续可见，但不以额外按钮或新状态源实现。
- R6：使用 Avalonia 已安装的原生菜单/上下文菜单能力，不新增依赖、图标集、通用 CommandBar 抽象或新命令。
- R7：保持 Cards/Details/Names 三视图、拖拽、快捷键、自动化名称和全部命令语义不变。

## Acceptance Criteria

- [ ] AC1：标题区只直接展示确认开关、选择/刷新菜单和“一键启动已勾选”，不再并列全选、清空、刷新三个按钮。
- [ ] AC2：次级动作行只直接展示新增、Cards 分组、发现、管理菜单、启动组维护菜单和可见计数。
- [ ] AC3：三个菜单中的每个菜单项绑定原有命令，命令文件和服务层无行为修改。
- [ ] AC4：结构契约测试固定直接可见动作集合、菜单项、自动化名称，并证明卡片仍为“启动 + 更多”。
- [ ] AC5：键盘可打开菜单并执行所有折叠动作；删除启动组仍经过既有确认语义。
- [ ] AC6：没有新增依赖、图标集、窗口合并、ViewModel 状态或业务逻辑。
- [ ] AC7：Release tests、git diff --check、tools/verify.ps1、publish 与 GUI smoke 全绿。

## Out of Scope

- V-03 对话框重排、V-04 无障碍全量审计、V-05 图标集、V-06 响应式矩阵。
- 合并 CommandManagementWindow 与 DirectoryManagementWindow。
- 修改命令实现、持久化、状态文案或配置 schema。
- 隐藏高频启动动作或以仅图标按钮替代文字标签。
